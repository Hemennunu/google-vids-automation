# Section 8: Worked Examples



## Definition

The path models how to choose sensors, fog, cloud, or Big Data analytics based on the scenario.



## Lead

The following worked examples illustrate how the concepts of Big Data, Cloud Computing, Fog Computing, and the Internet of Things can be applied to realistic scenarios in the Ethiopian context. Each example presents a problem statement, followed by a step-by-step analysis and recommended solution.



## Paragraphs

Analysis and Solution. This scenario demonstrates the integration of IoT, Fog Computing, and Cloud Computing. IoT soil moisture sensors and weather stations would be deployed across the farms to collect environmental data. Since internet connectivity is limited, fog computing would be essential: a local fog node installed at the cooperative's central facility would collect data from nearby sensors via LoRaWAN, a low-power wide-area network protocol ideal for rural areas with sparse connectivity. The fog node would process sensor readings locally, generating immediate irrigation recommendations that farmers can access through a simple mobile application without requiring cloud connectivity. At the end of each day or when connectivity is available, the fog node would synchronise aggregated data to a cloud-based analytics platform. In the cloud, machine learning algorithms would analyse historical data to identify patterns linking environmental conditions to coffee quality scores, enabling the cooperative to refine its farming practices over time. This architecture ensures that farmers receive real-time guidance even in areas with poor internet access, while still benefiting from the analytical power of cloud computing.

Analysis and Solution. This is a classic Big Data problem. Ethio Telecom generates vast volumes of data at high velocity from its network infrastructure. The solution involves building a Big Data analytics platform on cloud infrastructure capable of ingesting, storing, and processing streaming network data. Using tools such as Apache Hadoop or Apache Spark deployed on a cloud platform, the system would analyse patterns in call drops, data throughput, and network congestion in real time. Predictive analytics models would identify base stations at risk of failure before they actually fail, enabling proactive maintenance. Data visualisation dashboards would present network health information to operations staff in an intuitive format. The Big Data platform would also analyse customer usage patterns to identify opportunities for new service offerings and targeted promotions. By migrating to a cloud-based Big Data analytics platform, Ethio Telecom can achieve real-time network monitoring and optimisation without the capital expenditure of building its own large-scale data centre.

Analysis and Solution. The ECX processes structured transaction data including commodity grades, volumes, prices, buyer and seller information, and timestamps. This data, combined with external data sources such as satellite weather imagery, international coffee price indices from the New York and London exchanges, and production forecasts from the Ministry of Agriculture, constitutes a rich Big Data resource. A cloud-based data warehouse would integrate these diverse data sources. Machine learning models, including time series forecasting algorithms such as ARIMA and Long Short-Term Memory networks, would be trained on historical data to predict short-term and long-term price trends. The resulting predictions would be delivered to farmers, traders, and policymakers through a web-based dashboard and mobile application. This system would enable Ethiopian coffee farmers to make informed decisions about when to sell their harvest, potentially increasing their income and reducing price risk. The cloud infrastructure ensures that the system can scale to handle increasing data volumes as more commodities and data sources are added over time.



## Examples

Scenario. A coffee cooperative in the Sidama region manages 500 smallholder farms spread across a mountainous area with limited internet connectivity. The cooperative wants to monitor soil moisture, temperature, and sunlight levels across all farms to optimise irrigation and improve coffee bean quality.

Scenario. Ethio Telecom wants to reduce network downtime and improve service quality for its seventy million subscribers. The network operations centre receives millions of call detail records and network performance metrics every hour, making manual analysis impractical.

Scenario. The Ethiopian Commodity Exchange wants to develop a system that predicts coffee price fluctuations based on historical transaction data, weather patterns, global market trends, and production forecasts.

creating, administering, and using applications.

maintenance by just accessing software via the Internet rather than installing
and maintaining it.
